# Вытекание жидкости из сосуда (закон Торричелли)

![Скриншот программы](docs/screenshot.png)

Программа моделирует вытекание жидкости из открытого сосуда через малое отверстие. По закону Торричелли скорость истечения зависит от высоты столба жидкости над отверстием: по мере того как уровень снижается, скорость падает. Пользователь задаёт параметры сосуда и жидкости, программа строит графики зависимости скорости от высоты и от времени и позволяет сохранить результаты в CSV или JSON.

---

## Физическая модель

Уравнение Бернулли для сечения 1 (поверхность жидкости) и сечения 2 (отверстие) в открытом сосуде, где давления равны, а сечение отверстия много меньше сечения сосуда, даёт формулу Торричелли:

```
υ = √(2 · g · h)
```

где `h` — высота столба жидкости над отверстием, `g = 9,8 м/с²`.

Алгоритм расчёта (по учебному пособию «Компьютерное моделирование в физике», пример 6, с. 83–90):

1. Задаются плотность жидкости, начальный уровень, высота отверстия, шаг по высоте `dh` и шаг по времени `dt`.
2. Пока уровень выше отверстия, считается перепад давления `Δp = ρ · g · (h − h_отв)` и скорость `υ = √(2 · Δp / ρ)`.
3. Уровень уменьшается на `dh`, время увеличивается на `dt`, расчёт повторяется.
4. Результат — набор точек `(время, высота, скорость)` для графиков `υ(h)` и `υ(t)`.

Режимы расчёта:

- **«Как в методичке»** — алгоритм выше (основной режим).
- **«Динамика»** (план) — численное интегрирование уравнения `dh/dt = −(a/A) · √(2·g·h)`, где `a` — площадь отверстия, `A` — площадь сечения сосуда, со сверкой с аналитическим решением.

```
                ▼                              ▼
┌───────────────────────────────┐   ┌─────────────────────────┐
│  VirtualLab.Export            │   │  VirtualLab.Core        │
│  • запись результатов в CSV   │──▶│  • физика и solver      │
│  • запись результатов в JSON  │   │  • модели данных        │

```

Правила зависимостей:

| Проект | Может ссылаться на | Не может ссылаться на |
| :--- | :--- | :--- |
| `VirtualLab.Core` | только стандартную библиотеку .NET | `Export`, `UI`, Avalonia |
| `VirtualLab.Export` | `Core` | `UI` |
| `VirtualLab.UI` | `Core`, `Export` | — |
| `VirtualLab.Core.Tests` | `Core` | `UI` |

**Core не ссылается на UI.** Core ничего не знает о кнопках и окнах, UI ничего не знает о физике. Это позволяет работать над слоями параллельно. Соблюдение правила проверяется в CI.

## Контракты между проектами

Проекты общаются через C#-типы из `VirtualLab.Core`. Контракт фиксируется заранее отдельным PR, чтобы Core, Export и UI могли работать параллельно (UI на время разработки использует заглушку solver).

```csharp
// VirtualLab.Core
public sealed record TorricelliParameters(
    double Density,        // плотность жидкости ρ, кг/м³
    double InitialHeight,  // начальный уровень от дна, м
    double HoleHeight,     // высота отверстия от дна, м
    double HeightStep,     // шаг по высоте dh, м
    double TimeStep,       // шаг по времени dt, с
    double Gravity = 9.8); // ускорение свободного падения, м/с²

public sealed record SimulationPoint(
    double Time,           // время, с
    double Height,         // уровень от дна, м
    double Velocity);      // скорость истечения, м/с

public sealed record ValidationError(
    string Code,           // машинный код ошибки
    string Field,          // имя свойства TorricelliParameters
    string Message);       // объяснение для пользователя

public interface ITorricelliSolver
{
    IReadOnlyList<ValidationError> Validate(TorricelliParameters parameters);
    IReadOnlyList<SimulationPoint> Solve(TorricelliParameters parameters);
}

// VirtualLab.Export
public interface IResultExporter
{
    void Export(IReadOnlyList<SimulationPoint> points, string path);
}
```

### Единицы измерения

- **Длины** — метры
- **Время** — секунды
- **Скорость** — метры в секунду
- **Плотность** — кг/м³
- **Числа в файлах** — с десятичной точкой (инвариантная культура), поля JSON в camelCase

### Формат CSV

```
time,height,velocity
0,1,4.2
0.1,0.99,4.1766
```

### Формат JSON

```json
{
  "points": [
    { "time": 0.0, "height": 1.0, "velocity": 4.2 },
    { "time": 0.1, "height": 0.99, "velocity": 4.1766 }
  ]
}
```

### Проверка параметров

Некорректные параметры отклоняются до расчёта: плотность больше нуля, начальный уровень выше отверстия, шаги `dh` и `dt` больше нуля. Состав и формат сообщений об ошибках согласуются в первом PR с контрактами.

## Сборка и запуск

Требования: .NET 9 SDK и Visual Studio с поддержкой .NET 9 (для Avalonia удобно установить расширение Avalonia for Visual Studio).

```
git clone https://github.com/lab-VPE/lab2.git
cd lab2
dotnet restore
dotnet build
dotnet test
dotnet run --project src/VirtualLab.UI
```

Или откройте `VirtualLab.sln` в Visual Studio и запустите проект `VirtualLab.UI`.

## Правила совместной работы

- **Ветки:** `main` — стабильная, защищена. Работа ведётся в личных ветках от `main`: `core/...`, `ui/...`, `export/...`, `docs/...`, `ci/...`.
- **Прямой push в `main` запрещён.** Только через Pull Request: одно одобрение от другого участника и успешная сборка в CI.
- **Ревью по кругу:** PR Core проверяет UI, PR UI проверяет тимлид, PR тимлида проверяет Core. Каждая задача заводится как issue с исполнителем и закрывается через `Closes #N` в PR.
- **Ветки живут недолго** — 2–3 дня, большие задачи режутся на несколько PR.
- **Откат — только `git revert`**, не `git reset`.
- **Сообщения коммитов** — в повелительном наклонении по шаблону `тип(область): описание`, например `feat(core): add Torricelli solver`, `fix(ui): fix decimal comma parsing`.
- **`git status` — в любой непонятной ситуации.**
